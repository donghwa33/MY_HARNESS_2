# 독립 검토

1. 이전 대화를 가정하지 않는다. STATE·FINDINGS·DECISIONS 와 결론에 관련된 코드·표·데이터만 읽는다.
2. 결론을 깨뜨릴 대안 가설과 반증 방법을 쓴다.
3. 버그를 찾는다: 필터 순서, 조인 손실, 날짜 경계, 집계 단위, 보정 중복, 하드코딩.
4. 요구사항과 성공 기준 충족 여부를 판정한다.
5. 핵심 숫자 최대 3개를 다른 방법으로 다시 계산해 src/recheck.py 와 outputs/tables/recheck.csv 에 남긴다.
6. work/REVIEW.md 에 R-번호로 쓴다: 지적 / 맞으면 결론이나 조치가 바뀌는가(예·아니오) / 권장 판정. 최종 판정은 사람이 한다.
결론이나 조치를 바꾸지 않는 지적은 표현 보완으로 다루고, 결론의 확신도를 낮추는 근거로 쓰지 않는다. 기존 코드는 수정하지 않는다.
