# 04. S3 핵심 작업 (분석·구현)

순서: 넓게 한 번 → 정식화 → 검증 기준 → 접근 비교 → 나눠 보기 → (웹 서비스) → 정리.
프롬프트는 README 의 위임 프롬프트 틀(목표·입력·출력·조건·하지 마라·완료 조건)로 준다.

## 1. 넓게 한 번
```
데이터와 요구사항을 한 번에 넓게 훑어, 핵심 질문별 잠정 답과 근거 파일을 표로 만들고 멈춰라. 깊은 분석·구현은 아직 하지 마라.
```

## 2. 정식화 (사람이 확정)
```
문제를 입력·출력, 조건(반드시 지킬 / 점수로 볼 / 범위 밖), 지표 정의(분모 포함)로 정리해 초안을 쓰고 멈춰라.
서비스가 있으면 work/ARCHITECTURE.md 6절에, 없으면 work/FINDINGS.md 맨 위에.
```
사람이 확인·수정해 `(사람)` 으로 확정한다. 정의가 애매하면 요청자에게 묻는다.

## 3. 검증 기준 먼저
```
조건 위반과 지표를 계산하는 함수(검증기)만 만들고, 내가 답을 적어 둔 작은 예제로 테스트하라. 알고리즘·분석 코드는 아직 만들지 마라.
```

## 4. 접근 비교
```
<기준선> 과 <주력 방법> 을 같은 입력 세트(작은 것 / 실제 크기 / 극단)로 실행해, 같은 검증기로 조건 위반·지표·시간을 비교표로 저장하라.
선택 규칙은 <위반 0 → 지표 → 시간>. 추천과 이유를 쓰고 내 결정을 기다려라.
```
결정은 DECISIONS 에 `(사람)` 으로. 알고리즘 예시는 harness/scaffold/WEBAPP.md 7절.

## 5. 나눠 보기
```
결론이 일부 데이터에만 기대는지 확인하라. <그룹·기간·조건> 별로 나눠 같은 결론이 나오는지, 전체로 본 결과와 나눠 본 결과가 다르면 그 이유를 표로 저장하고 멈춰라.
```
원인 분석 작업이면 `$stratify-analysis` 로 깊게 들어간다.

## 6. 웹 서비스 (요구사항에 화면·서비스가 있을 때)
1. 설계: `work/ARCHITECTURE.md 를 harness/templates/ARCHITECTURE.md 형식으로 초안 작성하고 멈춰라.` → 사람이 `(사람)` 으로 확정
2. 구조: `harness/scaffold/WEBAPP.md 의 폴더·계층·DB 규칙대로 빈 구조와 test_boundaries.py 를 만들고 통과시켜라.`
3. 계산: `2~4 에서 정한 검증기·알고리즘을 core 로 옮기고 tests/test_core.py 로 확인하라. 웹·DB 는 아직 만들지 마라.`
4. 저장·흐름·HTTP: `schema.sql·repo·services·api 를 WEBAPP.md 4·5·8절대로 만들고 10절 테스트를 통과시켜라.`
5. 화면: `static/index.html 을 WEBAPP.md 9절대로 만들어라.` → `bash run.sh` 후 미리보기에서 사람이 확인

## 7. 정리
```
FINDINGS 에 F-번호로 정리하고, 결과에 영향이 큰 판단만 EXPLAIN 에 추가하라.
```
사람이 설명 못 하는 문장은 고치거나 지운다. 필요하면 `$redteam` → 커밋 → `$handoff`.
